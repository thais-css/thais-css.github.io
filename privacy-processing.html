Python application

Privacy-first data processing tool

A local application that turns complex data archives into consistent, password-protected delivery packages.

The problem

Preparing an export meant opening dozens of folders and JSON files, deciding what to copy into a spreadsheet, converting it to PDF, then creating a protected ZIP and password separately. The result depended too much on who was handling the request.

Operational change

Before and after

The tool brings the steps together and gives operators one clear path to follow.

Before

Manual, fragmented work

  1. Open the archive and navigate its nested folders.
  2. Find relevant JSON files and decide what to copy.
  3. Build a spreadsheet with a format that could vary by operator.
  4. Convert it to PDF, create a protected ZIP and generate a password in separate steps.

After

One repeatable workflow

  1. Upload a supported archive into a guided local interface.
  2. Select the relevant path for the delivery purpose.
  3. Generate a standardized document or preserve the required raw material.
  4. Download a password-protected package, with temporary work files cleared after delivery.

What I built

I built a local Python application with a guided web interface. It accepts ZIP, TAR and TAR.GZ archives, normalises their structures and follows the appropriate processing path.

It can turn structured data into a standard PDF or keep the required raw files. In both cases, it prepares a password-protected package and clears temporary files afterwards.

Archive upload → validation & extraction → normalized structure → selected processing path → structured PDF or raw-data package → password-protected delivery → temporary-file cleanup

Technical design

Application

Python + Flask

A local web interface guides non-technical users through distinct processing paths.

Architecture

Modular services

Routes, extraction, document generation, packaging and cleanup are separated by responsibility.

File handling

Archive normalization

The workflow accommodates ZIP, TAR and TAR.GZ inputs, including nested folder structures.

Quality

Automated tests

The codebase contains 69 automated tests covering expected behavior and edge cases such as corrupted archives and TAR path traversal.

Privacy

Local processing

The application is configured to operate on localhost rather than send working files to an external service.

Retention

Ephemeral files

Temporary working folders are cleared at startup, after delivery and after a period of inactivity.

The result

The process no longer depends on manually exploring JSON files, building individual spreadsheets and switching between tools to prepare a delivery.

The application’s internal code and proprietary formats are not included here.

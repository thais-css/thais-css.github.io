Technical case study · Python application

Privacy-first data processing tool

A local application that replaced a fragmented, manual workflow for complex data exports with a guided and consistent delivery process.

The problem

Preparing a data export previously meant navigating dozens of folders and JSON files, deciding what to copy into a spreadsheet, converting that file to PDF, then separately creating a password-protected package and communicating its password.

The workflow was manual, inconsistent between operators and difficult to repeat reliably for batch requests.

Operational change

From scattered handoffs to one guided flow

The value was not simply creating a PDF. It was replacing a chain of operator decisions and disconnected tools with a repeatable delivery process.

Before

Manual, fragmented work

  1. Open the archive and navigate its nested folders.
  2. Find relevant JSON files and decide what to copy.
  3. Build a spreadsheet with a format that could vary by operator.
  4. Convert it to PDF, create a protected ZIP and generate a password in separate steps.

After

One repeatable workflow

  1. Upload a supported archive into a guided local interface.
  2. Select the relevant path for the delivery purpose.
  3. Generate a standardized document or preserve the required raw material.
  4. Download a password-protected package, with temporary work files cleared after delivery.

What I built

I built a local Python application with a guided web interface. It accepts ZIP, TAR and TAR.GZ archives, normalizes their structures and applies the relevant processing path for the delivery purpose.

For document-oriented paths, it turns structured data into a consistent PDF. For other paths, it preserves the required raw material. The final output is a password-protected delivery package, followed by automated cleanup of temporary files.

Archive upload → validation & extraction → normalized structure → selected processing path → structured PDF or raw-data package → password-protected delivery → temporary-file cleanup

Technical design

Application

Python + Flask

A local web interface guides non-technical users through distinct processing paths.

Architecture

Modular services

Routes, extraction, document generation, packaging and cleanup are separated by responsibility.

File handling

Archive normalization

The workflow accommodates ZIP, TAR and TAR.GZ inputs, including nested folder structures.

Quality

Automated tests

The codebase contains 69 automated tests covering expected behavior and edge cases such as corrupted archives and TAR path traversal.

Privacy

Local processing

The application is configured to operate on localhost rather than send working files to an external service.

Retention

Ephemeral files

Temporary working folders are cleared at startup, after delivery and after a period of inactivity.

The operational change

The tool replaced an unstandardized sequence of manual handoffs with a single, repeatable workflow. It reduces the need to explore raw JSON files, transcribe information into individual spreadsheets and perform document, packaging and password steps separately.
